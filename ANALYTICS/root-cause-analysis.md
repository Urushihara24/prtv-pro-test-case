## 🔍 Анализ по категориям

### 1. Интеграции (10 багов, 22%)

#### Симптомы
- Google OAuth не подключается (PRD-002)
- Ресторанные меню недоступны (PRD-003, PRD-039, PRD-040)
- Соцсети/RSS не отдают контент (PRD-004)
- Нет валидации credentials

#### Root Causes
1. **Отсутствие валидации на бэкенде**  
   API принимает любые данные без проверки формата.  
   **Пример**: iiko принимает `TEST123@@` как API ключ.

2. **Неправильная обработка OAuth-токенов**  
   После авторизации токен не сохраняется или не передаётся корректно.  
   **Пример**: Google OAuth — кнопка остаётся "+ Подключить".

3. **Отсутствие моков для тестирования**  
   Невозможно протестировать интеграции без реальных credentials.

#### Рекомендации
- ✅ Добавить валидацию на уровне API (DTO, валидаторы)
- ✅ Реализовать корректное хранение OAuth-токенов
- ✅ Создать моки для тестирования интеграций
- ✅ Добавить контрактное тестирование (Pact)

---

### 2. Мобильная версия (6 багов, 13%)

#### Симптомы
- Главная страница не адаптирована (PRD-010)
- Редактор сломан (PRD-011, PRD-046)
- Текст и кнопки выходят за границы (PRD-033, PRD-036)

#### Root Causes
1. **Адаптивность не была приоритетом**  
   CSS написан только для десктопа, мобильная версия "доделана" в конце.

2. **Нет мобильного QA в команде**  
   Тестирование проводилось только на десктопе.

3. **CSS-стили не пересчитываются для ≤768px**  
   Медиа-запросы отсутствуют или работают некорректно.

#### Рекомендации
- ✅ Внедрить Mobile-First подход
- ✅ Добавить мобильного QA в команду
- ✅ Использовать responsive design (flexbox, grid)
- ✅ Тестировать на реальных устройствах (не только эмуляторах)

---

### 3. Редактор (5 багов, 11%)

#### Симптомы
- Длинный текст выходит за границы (PRD-016)
- Вертикальное видео повёрнуто (PRD-017)
- Drag'n'drop не работает (PRD-018)
- Кнопка добавления видео не работает (PRD-045)

#### Root Causes
1. **Некорректная обработка edge cases**  
   Длинные тексты, большие файлы не учитываются в логике.

2. **Отсутствие автоматических тестов**  
   UI-логика не покрыта тестами, баги находятся только вручную.

3. **Сложная логика drag'n'drop**  
   Реализация не учитывает все состояния (hover, active, disabled).

#### Рекомендации
- ✅ Добавить обработку edge cases (валидация, ограничения)
- ✅ Внедрить E2E-тесты для редактора (Cypress, Playwright)
- ✅ Упростить логику drag'n'drop (использовать готовые библиотеки)

---

### 4. ТВ-приложение (4 бага, 9%)

#### Симптомы
- СШ по номеру не открывается (PRD-008)
- Потоки не воспроизводятся (PRD-009)

#### Root Causes
1. **Изменения в API не синхронизированы с ТВ-клиентом**  
   Бэкенд обновлён, ТВ-приложение не знает о новых эндпоинтах.

2. **Нет автоматических тестов для ТВ**  
   Ручное тестирование ТВ не проводится регулярно.

3. **Отсутствие мониторинга**  
   Неизвестно, сколько пользователей столкнулось с проблемой.

#### Рекомендации
- ✅ Синхронизировать версии API и ТВ-клиента
- ✅ Внедрить автоматические тесты для ТВ (Appium)
- ✅ Добавить мониторинг ошибок (Sentry, LogRocket)

---

### 5. Биллинг (3 бага, 7%)

#### Симптомы
- Лицензии не суммируются (IMP-001)
- Нет сортировки (PRD-028)

#### Root Causes
1. **Бизнес-логика не формализована**  
   Неясно, как должны суммироваться лицензии.

2. **Отсутствие UX-исследований**  
   Неизвестно, как пользователи ожидают видеть лицензии.

#### Рекомендации
- ✅ Формализовать бизнес-логику (документация, диаграммы)
- ✅ Провести UX-исследования (интервью, опросы)

## 💡 Системные проблемы

### 1. Отсутствие автоматизации
**Проблема**: 95% тестов — ручные.  
**Влияние**: Медленная регрессия, пропуск багов.  
**Решение**: Внедрить E2E-тесты (Cypress, Playwright).

### 2. Нет CI/CD для тестирования
**Проблема**: Тесты запускаются вручную, не интегрированы в пайплайн.  
**Влияние**: Баги находятся поздно, дорого исправлять.  
**Решение**: Интегрировать тесты в CI/CD (GitHub Actions, GitLab CI).

### 3. Отсутствие контрактного тестирования
**Проблема**: Интеграции ломаются при изменениях API.  
**Влияние**: 22% багов связаны с интеграциями.  
**Решение**: Внедрить контрактное тестирование (Pact).

### 4. Нет мобильного QA
**Проблема**: Мобильная версия тестируется "в последнюю очередь".  
**Влияние**: 13% багов, 50% High.  
**Решение**: Добавить мобильного QA в команду.
